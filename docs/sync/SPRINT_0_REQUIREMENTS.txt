==================================================
PART B
RESEARCH HUB v0.3
LOCAL-FIRST RESEARCH SYNC
==================================================

v0.3 的核心产品方向：

Research Hub 不再只是：

Single-PC Research Application

而需要逐步升级为：

Local-first Multi-device Research Workspace


目标设备：

Windows PC
Phone
Tablet

未来还包括：

Codex
ChatGPT


但核心原则：

每个设备可以拥有自己的本地工作状态。

没有网络时：

仍可以查看、记录和修改允许离线操作的数据。

恢复网络后：

通过 Sync Protocol 同步。

==================================================
B1. IMPORTANT ARCHITECTURE PRINCIPLE
==================================================

不要采用：

Mobile → always-online central database

作为唯一工作模式。

不要采用：

PostgreSQL database file sync

不要采用：

Git repository directly syncing database state

不要采用：

Last Write Wins

覆盖科研数据。


目标模型：

                Encrypted Sync Relay

                       │
                    Sync

         ┌─────────────┼─────────────┐
         │             │             │
       Windows       Phone         Tablet

       Full Store   Local Store    Local Store
         │
      PostgreSQL
      MinIO
         │
       Codex


Windows PC：

Primary Full Storage Node

但注意：

Primary ≠ conflict winner。

Primary 只代表：

完整数据
完整 Artifact
长期存储
备份节点
Codex execution node


它不意味着：

发生冲突时电脑版本永远覆盖手机。

==================================================
B2. CLOUD ROLE
==================================================

云端不能默认设计成：

Research Hub Source of Truth Database。


优先设计：

Encrypted Sync Relay


职责：

暂存加密 ChangeSet
保存设备同步游标
保存对象版本信息
暂存允许同步的加密 Artifact
支持异步设备 Push / Pull


云端服务器默认：

不应拥有端到端加密密钥。

科研数据内容应尽可能：

E2E encrypted。


未来即使 Sync Relay 被攻破：

攻击者也不应直接获得科研内容。

B32. FORMAL SYNC INVARIANTS
==================================================

4.

5.

7.

8.

9.
