# Research Hub v0.2 交付报告

日期：2026-10-07（Asia/Shanghai）。Sprints 0–3 对应 RH-004–RH-007；使用简体中文，保留个人科研 Hub 和 Core/Module 架构。GitHub 目标为私有 `Zh9426/ResearchHub`，开发分支 `codex/researchhub-v0.2`。个人数据在本机 PostgreSQL/MinIO，未迁移到第三方云。

## IMPLEMENTED

| 要求 | 最终交付行为 |
|---|---|
| 1. Architecture changes | 根据实际权限、查询、生命周期、工作流、研究追踪和连接需求拆分后端模块；Human UI 与语义 MCP 分开。沿用 Next.js/FastAPI/PostgreSQL/MinIO。 |
| 2. Database migrations | 新增 0002 基础保护、0003 工作流、0004 历史/追踪、0005 代码来源；0001 及已提交历史迁移保持不变。 |
| 3. Module versioning | 项目冻结 module_version/module_snapshot；Registry 的当前定义不会自动改旧项目，人工预览版本差异后升级。 |
| 4. Capability system | 七类组合能力决定录入方式；模块决定科研字段与边界，导航/表单/视图/组件由 manifest 驱动。 |
| 5. Human / AI authority | AI 可结构化记录，不可确认参数、验证科学证据/指标、写人工结论、接受决策或通过关卡；星标要求显式用户请求。服务端执行所有权、scope 和生命周期检查。 |
| 6. Research Run UX | 四字段快捷创建；目标、观察、核心参数和独立 AI/人工结论首屏，条件/代码/详细字段折叠，按工作方式录入；null、零、负结果均保留。 |
| 7. Highlight system | 星标与科研结果独立，保留类型/理由/操作者/时间；可以星标负结果，克隆不继承星标。 |
| 8. Activity / Audit | 活动展示可隐藏，不可变审计仍保留；项目/时间/操作方/资源筛选、分页和审计导出。 |
| 9. Search / pagination | 数据库查询、完整计数、筛选、排序；参数/指标/历史/差异/语义 MCP 按页返回。不能把当前页当全部数据。 |
| 10. Export | 项目 ZIP/Markdown、Audit JSONL；Bundle 校验预览与人工原子确认，失败回滚并清理对象。导出有明示容量上限，不能替代完整备份。 |
| 11. Lineage | 显式克隆继承、父子关系、参数/指标完整差异、谱系导航；不继承科研确认、观察、结论或完成结果。 |
| 12. Evidence traceability | 参数/指标来源历史、来源与文件引用、正反向追踪和降级影响；证据降级使相关 Gate 重新阻塞。 |
| 13. Mobile | 响应式快速笔记、实验、照片/视频和任务状态，精简导航、可触达保存；受限签名/50 MiB 上传，PWA 保留已有静态离线边界。 |
| 14. MCP | 9 READ + 9 WRITE 语义工具及 3 兼容别名；不开放 SQL/shell/任意服务器文件。register_artifact 仅关联已存在的同项目活动附件。 |
| 15. Codex integration | 本机启动器、配置示例、Plugin/Skill 包、真实 CLI 验收脚本；真实宿主调用及审计已验证，长期个人连接需配置专属令牌。 |
| 16. ChatGPT integration | 官方 Secure MCP Tunnel、HTTPS/OAuth 和 Plugin 包装评估及中文连接说明已交付；实际远程连接不在已实现事实中。 |
| 17. GitHub integration | 项目与 Run 保存代码仓库、分支、40 位 SHA、同仓库 Issue/PR；展示可点击来源。GitHub 作为代码来源，不替代科研事实存储。 |

归档、回收站、恢复、30 天后人工永久删除、引用保护和可重试对象清理贯穿各对象。个人桌面入口为 `Research Hub.lnk`，仓库内 `打开ResearchHub.cmd` 也可启动；已运行时直接使用现有服务。

## TESTED

**18. Test results**：最终后端/MCP/宿主验收脚本 127 项、前端 46 项通过；TypeScript、Ruff、原生与 Docker 生产构建通过。真实隔离服务验收共 23 项，包括 PostgreSQL/MinIO、HTTP、STDIO、并发、重启持久化、恢复到全新数据库/桶。负向故障注入的 SQLite/对象替身测试仅称单元测试。

个人数据库每次迁移前备份；最终 0005 的基线为 40 张原表、144 条原记录，原始列逐行保留。个人账号未重置，未导入 QA 数据。容器 QA 与个人服务使用不同端口、数据库、对象桶和凭据。

真实 Codex 客户端完成七步连接验收：查询项目、创建 Run、保存参数零/未知单位/未确认、指标零/合成来源、笔记、显式星标、读回；Hub 实际 UI 显示记录，审计身份 codex/mcp，人工结论空白，临时令牌已撤销。它与协议测试分开记载，不推断 ChatGPT 已连接。

场景 A–F 的依据：HDSP 仿真/参数修改/克隆/对比、ICE 测量负结果/星标、Codex 实际回写、证据降级/阻塞、活动隐藏后审计保留及项目导出均有分 Sprint 真实服务验收记录。场景 G 的完整 Registry 变更→旧项目冻结→预览→人工确认链由 SQLite HTTP 单元测试覆盖；真实 PostgreSQL 覆盖升级服务与行锁竞争，实际浏览器覆盖升级预览，不能合称真实 HTTP/UI 完整升级验收。见 [Sprint 0](SPRINT_0_REPORT.md)、[Sprint 1](SPRINT_1_REPORT.md)、[Sprint 2](SPRINT_2_REPORT.md) 和 [Sprint 3](SPRINT_3_REPORT.md)。这些软件合成场景不作为科研结果。

实际 IAB 操作覆盖桌面快捷创建、仿真与实验记录、星标、谱系/差异、Activity/Audit，以及 390×844 笔记/实验/PNG 上传。GitHub 来源编辑保存后读回，实际 PNG 字节哈希一致。界面全流程照片验收解决了 Sprint 2 的历史遗留项；实体相机仍单独列为未验证。

最终视觉复审依据 `researchhub-v02-concept.png` 与实际 IAB 截图，使用 frontend-app-builder/ui-ux-pro-max，并将布局、文案、字体、配色、密度和响应式逐项记录于 [VISUAL_V02_REVIEW.md](VISUAL_V02_REVIEW.md)。概念示例数字不植入用户数据，图示“重新分析”不构成授权功能。

- ChatGPT Web/Desktop/Mobile 实际连接；Plugin 包在宿主内实际安装；个人服务持续 Codex 会话。真实 Codex 验收仅操作隔离合成项目。
- 实体手机/平板、相机权限、PWA 安装、真实视频播放；浏览器手机视口不能替代硬件设备验收。
- GitHub Issue/PR 真实内容和自动存在校验；链接登记不能作为远端 API 同步证明。
- 场景 G 的真实 PostgreSQL HTTP/UI 全程模块变更、预览和人工确认；已有单元链路、真实 PG 升级/行锁与浏览器预览检查不能替代此项。

**19. Known issues**：Windows 初次 Codex TLS 连接失败，已使用系统原有可信公共 CA 的进程配置解决；没有关闭 TLS 或改变全局证书设置。非交互验收用临时工具授权配置，日常宿主仍按用户授权运行。Starlette/Pydantic/Vite 第三方提示仍存在；恶意重复 ZIP 警告来自特定测试输入。

**20. Technical debt**：部分 UI 组件仍密集、后端 router 可继续按职责拆分；嵌套 MCP 参数仍需结合导出 schema 阅读；分页为 offset，部分导出仍有容量上限；API 令牌基于当前用户范围而非项目绑定，未来应增加项目级/短期权限。数值曲线时间为保存时间，不推断实验时刻或因果关系。
