你现在需要在现有 Research Hub v0.1 基础上继续开发：

Research Hub v0.2
Connected & Modular Research Workspace

不要重新创建项目，不要推翻 v0.1。

==================================================
0. V0.2 PRODUCT DEFINITION
==================================================

v0.1 主要解决：

“科研事实如何被结构化保存。”

v0.2 主要解决：

“不同类型科研工作如何以更自然的方式进入 Research Hub，
并被研究者、Codex 和 ChatGPT 安全、低成本地共同使用。”

最终结构：

Researcher
     ↕
Human-first UI
     ↕
Research Hub
     ↕
Structured MCP
     ↕
ChatGPT / Codex


Research Hub 仍然是 Source of Truth。

不得把：

ChatGPT Memory
Codex 对话
GitHub
Markdown
AI Analysis

作为科研事实数据库的替代品。

2. PROJECT CUSTOMIZATION MODEL
==================================================

当前 Generic / HDSP / ICE Module 的方向正确。

但 v0.2 需要进一步引入：

Composable Research Capabilities

不要变成：

每个课题开发一套独立 App。

应采用：

Research Hub Core
        +
Capability Modules
        +
Project Preset
        +
Domain Workflow


定义通用 Capability 概念。

第一批建议：

code_simulation

lab_experiment

hardware_system

measurement_imaging

fabrication

data_analysis

literature_sources


具体命名可优化。

Capability 的目标是：

同一种科研工作方式可以被多个 Project Module 复用。

例如：

ICE：

code_simulation
lab_experiment
hardware_system
measurement_imaging
literature_sources


HDSP：

code_simulation
fabrication
lab_experiment
data_analysis
literature_sources


Generic：

用户自行选择。


Project Module 决定默认 Capability。

但项目创建后，允许用户：

enable capability

disable / hide capability

不要完全锁死。


注意：

Capability ≠ Project Module。

Project Module 描述：

“研究什么。”

Capability 描述：

“以什么科研方式开展工作。”

==================================================

v0.1 的 research:read / research:write 粒度不足。

AI 可以：

保存 Metric

创建 Task

创建 proposed Evidence

创建 proposed Decision


AI 不应该自动执行：

填写 Human Conclusion

把 Parameter 标记为最终人工确认

把 Evidence 直接标记为 validated / reproduced

把 Gate 设置为最终 passed

删除科研事实

清空 Audit

执行科研最终确认


为重要科研状态建立：

Human approval / confirmation rule。


至少确保：

Human Conclusion

Evidence validation

Gate passage

final parameter confirmation

只能由 human session 完成。


MCP 使用 API Token 时必须继续标记：

actor_type = codex / chatgpt


所有写操作继续进入 Audit。

但前端不能强迫用户填写这些字段。

可选：

is_highlighted = true


完全合法。


UI 要求：

只看星标记录

星标优先查看

Project Overview 增加：

建议提供 Filter：

允许 MCP 查询星标 Run。

==================================================
37. IMPORTANT PRODUCT PRINCIPLE
==================================================

Research Hub v0.2 应同时服务两种用户：

A. Researcher

需要：

简单

快速

清晰

专业

尽可能少的手工录入


B. AI Agent

需要：

结构化

明确 Schema

明确权限

可审计

可追溯


因此必须遵守：

Human UI ≠ AI API


人类不应该被迫填写数据库表。

AI 不应该模拟点击网页。


最终目标：

研究者负责科研判断。

Codex 负责执行与结构化记录。

ChatGPT 负责理解、分析和规划。

Research Hub 负责保存长期、可验证、可追溯的科研事实。


现在开始 Research Hub v0.2 开发。
